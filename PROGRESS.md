## Decisions & notes
- Stack and every architectural decision below came out of a single planning conversation on 2026-07-14; the full file-by-file spec (every model/controller/route/component, with code) lives in that conversation's history, not in this repo's committed files (though the actual working code from it is now in `backend/` and `frontend/`). If a future session needs the original planning rationale rather than what's in CLAUDE.md/the code itself, ask the user to re-share that conversation.
- **MongoDB must be a replica set** for the backend to fully work (transactions in issue creation) — see CLAUDE.md "Known gotchas" for the `dev-mongo.sh` setup. Don't assume a plain local `mongod` is sufficient.
- **GitHub push access was resolved** (2026-07-14): this machine's git credentials are for GitHub user `NeerajSkeyit`; the user added that account as a collaborator on `geralt000vnr/Jira-clone` and accepted the invite, and a subsequent push succeeded. If push fails again, check the invite/collaborator status first before assuming it's a new problem.
- **Multi-tenant**: `organizationId` on every collection, auto-scoped via `req.scope()`. Never query a tenant-owned collection without it.
- **Per-project roles**: `admin`/`manager`/`developer`/`tester`, stored on `ProjectMember`, differ per project for the same user. Sprint-id-keyed routes need a project lookup via the sprint first (`requireSprintProjectRole`), not the plain `requireProjectRole`.
- **Issue hierarchy**: Epic → Story/Task/Bug → Subtask via `parentId`; subtasks can't nest further.
- **Customizable workflows**: `Issue.statusId` refs a per-project `WorkflowStatus` (name/color/order editable; category `todo`/`in_progress`/`done` fixed and drives board/sprint logic). See CLAUDE.md for the full breaking-change/migration note.
- **File storage**: local disk now, behind `FileStorageInterface` so S3 (or similar) is a drop-in swap later, not a rewrite.
- **Concurrency**: optimistic locking via `Issue.version` + `expectedVersion` on every mutating call, including bulk ops (per-item, not all-or-nothing); `409` (or a per-item `failed` entry for bulk) on mismatch, client refetches.
- **Audit trail**: `IssueActivity` per field change, skips no-op changes. Sprint burndown's "actual" line is derived entirely from this trail — no separate burndown-tracking mechanism.
- **Soft deletes** everywhere via `deletedAt`; `req.scope()` filters it out automatically. Deleting an issue cascades soft-delete to its subtasks (single or bulk delete).
- **Real-time**: Socket.io room per project board; broadcasts + async email queue on issue/comment/attachment/worklog changes.
